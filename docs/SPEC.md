# BeamSync Technical Specification

## 1. Scope & Components

BeamSync is a standalone, unidirectional streaming directory migration and incremental synchronization stack built for developer workspaces (tens of thousands of small source files alongside multi-GB build/database artifacts).

The system consists of three components:
1. **`beamsync-server` (Central Coordinator)**: Always-on pairing rendezvous, regional `RelayMap` registry, embedded UDP STUN responder, and offline AWS SigV4 presigner bound directly to Cloudflare R2 without proxying bulk payloads through the control plane.
2. **`beamsync-edge-relay` (Stateless Regional Edge Relay)**: Horizontally deployable binary cut-through and UDP STUN daemon (`sha`, `hkg`, `sgp`, `tyo`, `fra`, `sjc`, etc.) holding zero R2 credentials, zero database state, and zero session keys. Natively supports **domainless raw `IP + self-signed ECDSA P-256 TLS + SHA-256 certificate pinning + SNI suppression`** for regions without domain ICP filing.
3. **`beamsync` CLI / SDK**: Persistent local stat-cache + BLAKE3/FastCDC indexer, zero-knowledge Curve25519 PAKE handshake, 5-tier adaptive transport negotiation, streaming `BMSP` pack encryption, and atomic target workspace materialization.

## 2. Five-Tier Adaptive Transport Hierarchy

| Priority | Tier | Trigger Condition | Data Plane Framing | R2 Operations |
| :--- | :--- | :--- | :--- | :--- |
| Tier 0 | `LOCAL_IPC` | Matching `HMAC(K_host, machineId:bootId)` across peers | Unix Domain Socket (`0666`) / Loopback TCP + mutual `K_transport` auth, uncompressed pack stream | 0 |
| Tier 1 | `P2P_DIRECT` | Overlay/Dual-Stack LAN TCP Happy Eyeballs winner, or STUN UDP hole punch | Framed TCP (`IPv4` + `IPv6`) or `BMU1` AEAD UDP with adaptive SRTT/AIMD + 64-bit SACK + `zstd` | 0 (mid-flight R2 fallback on drop) |
| Tier 2 | `EDGE_RELAY` | No direct path ready within the `250 ms` grace window (or P2P blocked by Symmetric NAT / UDP firewall) with active regional Edge Relay (`<= 512 MiB` default or `--prefer-edge-relay`) | `argmin(RTT_source + RTT_target)` regional WSS cut-through (supports SNI-free pinned IP+TLS) + mutual `K_transport` auth + sliding-window binary stream | 0 (hot upgrade to Tier 1 at a pack boundary; mid-flight R2 fallback on drop) |
| Tier 3 | `STREAM_RELAY` | No Edge Relay available and missing delta `<= 8 MiB` | End-to-end encrypted WebSocket control-plane slices | 0 |
| Tier 4 | `R2_PIPELINE` | Large cross-region bulk workspace transfers | Concurrent presigned `PUT`/`GET` pipeline directly against Cloudflare R2 with overlapping upload & download | Missing non-CAS packs only |

## 3. Networking Primitives

1. **Smart NIC Discovery & Dual-Stack IPv6**: Filters unroutable container bridges (`docker*`, `br-*`, `veth*`, `cni*`, `virbr*`, `flannel*`, `cali*`) and link-local addresses (`169.254.0.0/16`, `fe80::/10`), ranking **Overlay Mesh VPNs** (`tailscale*`, `wg*`, `zt*`, `100.64.0.0/10`, `fd7a:115c:a1e0::/48`) ahead of **Global Unicast IPv6** (`2000::/3`), ahead of **LAN IPv4 / ULA IPv6**.
2. **RFC 8305 Happy Eyeballs Candidate Racing**: Staggers direct socket attempts by `100ms` in parallel, adopts the first mutually authenticated channel, and aborts all remaining in-flight attempts via `AbortController`.
3. **Multi-STUN NAT Mapping Classification & Stride Prediction**: Queries two distinct STUN endpoints on the same bound UDP socket (supporting both IPv4 `0x01` and IPv6 `0x02` `XOR-MAPPED-ADDRESS`), classifies `endpoint_independent` (Cone NAT) vs `symmetric`, predicts sequential ports (`port2 + k * stride`) for small strides (`1..8`), and skips futile UDP timeouts when both peers sit behind unpredicted Symmetric NAT.
4. **Domainless IP+TLS Edge Relay Protocol**: Generates ECDSA P-256 X.509v3 certificates in memory via `node:crypto`, advertises `certSha256` over HMAC-signed heartbeats, suppresses TLS `ClientHello` SNI (`servername: ""`), verifies the raw DER SHA-256 pin on `secureConnect` before sending HTTP bytes, enforces coordinator-minted upgrade tickets, and applies `4 MiB` / `1 MiB` room backpressure.
5. **Control-Plane Keepalives & Token-Bucket Pacing**: Sends periodic `20s` WebSocket keepalives across Coordinator and Edge Relay sockets and enforces optional `--max-mbps` token-bucket bandwidth throttling on the four network tiers (`P2P_DIRECT`, `EDGE_RELAY`, `STREAM_RELAY`, `R2_PIPELINE`). `LOCAL_IPC` is not paced.
6. **Optimistic Relay Start & Hot Upgrade**: The source starts direct-path discovery right after `peer_confirmed` and keeps it running in the background (UDP punch budget `12 s` when a relay can carry the start, `1.5 s` otherwise; the target keeps punching for `20 s`). If an Edge Relay is eligible and no direct path is ready after `optimisticRelayGraceMs` (`250 ms`), the plan is sent with `selectedTier = EDGE_RELAY` and `directUpgradePending = true`. When a direct path completes, the source sends `direct_upgrade_offer {channel: "tcp" | "udp"}`; the target starts a reader on that channel and replies `direct_upgrade_answer {channel, accepted}`. On acceptance the source drains in-flight relay ACKs, ends the relay stream at the pack boundary, and sends the remaining packs on the direct channel. The Coordinator records `P2P_DIRECT` as the session tier. `source_transfer_plan.directChannel` tells the target which direct channel to read when both TCP and UDP are viable.
7. **Resumable Signaling**: Client messages carry `cseq`, server messages carry `sseq`. The Coordinator keeps a per-peer replay log (capped at `64 MiB`) and its last processed `cseq`; the client keeps an outbox of unacknowledged messages and its last seen `sseq`. `ping {ackSeq}` / `pong {ackSeq}` trim both sides; the client additionally sends an acknowledging `ping` after every `2 MiB` of received messages, so the replay log stays small during a control stream. After a socket loss the client reconnects (backoff `100 ms` to `2 s`, total budget `signalingReconnectBudgetMs`, default `30 s`) and sends `hello {resumeFromSeq}`; the Coordinator replays everything after `resumeFromSeq` and answers `resumed {lastClientSeq}`, upon which the client replays its outbox. Both sides drop duplicates by sequence number. Errors: `RESUME_UNKNOWN_PEER`, `RESUME_GAP`, and client-side `SIGNALING_LOST` when the budget is exhausted. Session state is in-memory, so a Coordinator restart is not resumable. When a paired peer stays without a signaling socket for `peerLossGraceMs` (default `45 s`, longer than the client reconnect budget), the Coordinator marks the session failed and sends the other peer `session_error {code: "PEER_LOST"}`. Waits for control stream segments, `source_transfer_plan`, and `session_committed` are unbounded on the client; waiting for the other peer to join is bounded by the pairing TTL (`10 min`). The session TTL (`2 h`) slides on every signaling message once both peers are paired.
8. **Outbound Proxy Tunneling**: `BEAMSYNC_PROXY` > `HTTPS_PROXY` / `HTTP_PROXY` (by target scheme) > `ALL_PROXY`, with `BEAMSYNC_NO_PROXY` / `NO_PROXY` bypass rules (`*`, exact host, domain suffix, `host:port`, IPv4 CIDR). Supports HTTP `CONNECT` (plain or TLS to the proxy, Basic auth) and SOCKS5 (no-auth, username/password, remote DNS). All HTTP(S) and WS(S) traffic of the CLI is tunneled; TLS, certificate pinning, and SNI suppression for pinned-IP Edge Relays are applied inside the tunnel. Tunnel failures surface as `PROXY_CONNECT_FAILED`.
9. **UDP Payload Probing & Keepalive**: Datagram size is `chunk payload + 45` bytes (plus `28` bytes of IPv4/UDP headers). After the punch the sender sends `MTU_PROBE` packets padded to payload sizes `1420, 1380, 1340, 1300, 1232` and adopts the largest size acknowledged by `MTU_PROBE_ACK`, otherwise stays at `1150`. A `KEEPALIVE` packet every `5 s` preserves the NAT binding while the channel is idle.
10. **Gateway Port Mapping (NAT-PMP, RFC 6886)**: In parallel with STUN classification the CLI asks the default IPv4 gateway (private addresses only; `/proc/net/route` on Linux, `route -n get default` on macOS/FreeBSD) on UDP `5351` for the external address and a UDP mapping of the punch socket (`7200 s` lifetime, `250 ms` budget). The mapped endpoint is advertised first unless the NAT is already `endpoint_independent`, renewed at half lifetime, and deleted (lifetime `0`) on session end.

11. **Ignore Rules**: The source evaluates layered rule sets with `.gitignore` pattern semantics while walking the tree; an ignored directory is not entered. Each layer is `{kind, source, baseDir, nameIndex, lines}` and patterns are anchored at `baseDir`. Layers are ordered by `kind` (`from` < `file` < `explicit`), then `nameIndex` (position of the ignore file name: `.gitignore` when enabled, configured names in order, `.beamsyncignore` last), then directory depth; the last matching rule across the applicable layers decides. Built-in patterns (`.beamsync/`, `.beamsync-*`, `.sync-staging-*`, `.DS_Store`) are checked first and are not negatable. Only regular files are read as ignore files. The effective layers travel to the target as `ignoreSpec` (`{version: 1, layers}`) in the sealed header of the `manifest` control stream, omitted when no user rule exists. After the atomic swap the target walks its previous tree top-down and moves every path that matches the spec and is absent from the new tree into the new tree (`rename`, same filesystem); paths present in the new tree always win, and built-in paths are never carried over. A failed move leaves the previous tree at `.<name>.beamsync-old-<sessionId>` and is reported in `preserveFailures` / `retainedBackupDir`. `deleteIgnored` on the target skips the carry-over.
12. **Sealed Control Streams**: The manifest and the target's list of known blob hashes do not travel as single messages. Each is a stream of newline-terminated records (`manifest`, written by the source: one header record `{version: "beamsync-manifest-stream/v1", treeVersion, totalLogicalBytes, entryCount, rootTreeDigest, ignoreSpec?}`, then one JSON record per entry in canonical order; `have_blobs`, written by the target: a first record holding the decimal hash count, then one 64-character hex hash per record). The byte stream is cut into segments of `1 MiB` (lowered automatically when the Coordinator's message limit is smaller; a cut may fall inside a record). Every segment is `zstd`-compressed and sealed with `ChaCha20-Poly1305` under `K_control`, with additional data `beamsync/control-stream/v1:<sessionId>:<stream>:<index>:<final|more>`, and sent as `control_stream_chunk {stream, index, final, payloadBase64}`. The reader requires strictly consecutive indexes starting at `0`, rejects a segment that decompresses to more than `64 MiB`, and answers each segment with `control_stream_ack {stream, index}`; the writer keeps at most `8` segments unacknowledged. A segment that fails authentication, arrives out of order, or belongs to another session or stream fails the session with `CONTROL_STREAM_INTEGRITY`; a stream whose record count differs from its header fails with `MANIFEST_INTEGRITY`. The Coordinator forwards chunks only from the stream's writer role and acknowledgements only from its reader role, and only after both `pake_confirm` messages. The source starts the `manifest` stream as soon as its scan finishes, in parallel with the target's hashing. `source_transfer_plan` carries `rootTreeDigest` and `manifestEntryCount` only; the target requires both to equal the sealed header and recomputes the digest over the received entries before it creates or modifies anything under the target directory. Blobs are grouped into packs of at most `~8 MiB` and at most `4096` blobs.
13. **Session Protocol Version**: `pake_confirm` carries `protocolVersion` (currently `2`) and the Coordinator relays it as `peer_confirmed.peerProtocolVersion`. A peer that sees a different or absent version stops with `PROTOCOL_VERSION_MISMATCH` right after pairing. Version `2` is the first negotiated version; builds from before it announce nothing and are rejected by newer builds.

## 4. Cryptographic & Bilateral Equilibrium Invariants

- **Zero-Knowledge Pairing (Curve25519 EKE PAKE)**: Masks ephemeral X25519 public keys with shared-phrase role masks to derive `K_root`, `K_transport`, `K_pack`, `K_control`, and `K_host`.
- **Blinded Custom Phrase Rendezvous**: Derives `slot = "k" + BLAKE3("beamsync/rendezvous/v1:" + phrase)[0..15]` client-side so plaintext phrases never leave the endpoints.
- **Convergent Namespace CAS**: Uses deterministic SIV AEAD under persistent `scopeNamespace` keys for encrypted cross-machine Cloudflare R2 deduplication.
- **Bilateral Pack Equilibrium & Atomic Commit**: Issues `grant_atomic_commit` strictly after `finalize_source_manifest` AND `sourceReceiptAt != null && targetReceiptAt != null` holds for every required `packId`, committing via local hardlink reuse and atomic directory staging.

## 5. Known Limitations

- No Edge Relay data-channel re-attach: a dropped relay connection falls back to `R2_PIPELINE` for unacknowledged packs.
- No Coordinator-restart recovery for in-flight sessions.
- Bandwidth pacing is per pack, not per byte: bursts of up to one pack, and inter-pack receive timeouts of `120 s` (TCP, Edge Relay) and `10 s` since the last datagram including keepalives (UDP).
- UDP payload probing is a one-shot search over fixed sizes, not continuous PMTUD.
- Port mapping covers NAT-PMP and UDP only (no UPnP IGD, no PCP, no TCP mapping).
- UDP candidates are IPv4 only; no QUIC transport; no single-port multiplexing of Coordinator, Edge Relay, and STUN.
- The protocol sets no limit on the number of entries, but both peers hold the whole manifest in memory, and the local state index is one JSON document that is serialized and parsed in a single call. Largest tree transferred end to end: `220,002` files (peak resident memory `742 MB` on the source, `806 MB` on the target). The stream layer alone was exercised with `1,000,000` synthetic entries (about `1.0-1.3 GB` resident).
- The source scan reads each file into memory in one call, so a file above `2 GiB` aborts the scan (`ERR_FS_FILE_TOO_LARGE`).
- Session protocol versions are compared for equality; there is no downgrade path. Interoperation with a build from before version `2` has not been tested; such a build has no mismatch check of its own.
- The source scan aborts on absolute symlinks, symlinks escaping the root, and unreadable paths; it skips sockets, FIFOs, and device nodes silently; it does not stop at mount points.
- The manifest has `dir` entries for empty directories only, so the mode of a non-empty directory is not transferred.
- The target's pre-plan scan is unaware of the source's ignore rules.
- The Coordinator cannot read, alter, reorder, or truncate a control stream unnoticed, but it can stall a session by withholding segments. It still sees `rootTreeDigest`, the entry count, missing blob counts and byte estimates, segment sizes, and the selected tier.
